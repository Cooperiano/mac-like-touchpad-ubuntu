# 我把 Ubuntu 触控板改成了 Mac 的逻辑：三指拖移，四指切桌面

我的测试机是一台 ASUS TUF Gaming F15，触控板是 ELAN1203，系统是 Ubuntu 24.04、GNOME
46。现在它的操作逻辑是这样的：

- 三指放在触控板上移动，直接拖动窗口、文件或文字选区；
- 四指左右滑动，切换工作区；
- 四指上下滑动，进入或退出 GNOME 总览；
- 四指捏合，显示桌面；
- 双指自然滚动，双指点击是右键。

这套配置已经整理成公开仓库：

<https://github.com/Cooperiano/mac-like-touchpad-ubuntu>

它不是换皮主题，也不是把几个快捷键绑到手势上。三指拖移发生在输入设备层，四指动画则交给
GNOME Wayland。两层各做一件事，冲突反而更少。

## Linux 触控板真正缺的不是“能用”

Ubuntu 默认已经支持双指滚动、轻触点击和掌压抑制。单看设置页面，好像什么都有。

但从 Mac 切过来，最容易形成肌肉记忆的并不是这些开关，而是三指拖移：光标放到窗口标题、
文件或文字上，三指一起移动，相当于按住鼠标左键拖动。手指不需要先用力按下，也不用保持
一根手指压住再用另一根手指移动。

GNOME 原生的三指手势做的是工作区导航。它很顺滑，但占用了三指。于是问题不是“给三指再
绑定一个快捷键”，而是要重新分配手势：

```text
三指：拖动
四指：工作区和总览
```

这也正是很多启用 macOS“三指拖移”的人熟悉的分工。

## 为什么只装一个手势软件不够

常见 Linux 手势工具擅长识别“向左滑”“向上滑”，然后执行快捷键。这适合切工作区，却不适合
拖动。

拖动不是一次离散动作。它需要持续输出：按下左键、根据手指位移移动光标、保持按下状态，最后
在手指抬起时释放。中间还要处理三根手指不同步落下、第四根手指晚到、部分手指先抬起，以及
内核丢帧后的状态恢复。处理不好就会出现三类很烦的问题：

1. 四指手势被误判成拖动；
2. 抬手后左键仍然处于按住状态；
3. 三指结束时产生幽灵右键或中键点击。

因此我把方案拆成两层。

第一层是
[`linux-3-finger-drag`](https://github.com/lmr97/linux-3-finger-drag)。它独占读取真实触控板，
把非三指事件原样交给一个虚拟触控板；当识别到三指拖动时，再通过虚拟鼠标输出左键拖动。

第二层是
[`Touchpad Gesture Customization`](https://github.com/HieuTNg/touchpad-gesture-customization)。它在
GNOME Wayland 中接管四指工作区、总览和捏合手势，动画能跟着手指连续移动，而不是等手指抬起
后突然触发一个快捷键。

整体链路是：

```text
ELAN 真实触控板
       │
       ▼
三指拖动代理
       ├── 虚拟触控板 ──► GNOME Wayland（一指、双指、四指）
       └── 虚拟鼠标 ────► 三指左键拖动
```

## X11 和 Wayland 的差别，在这里很具体

这套方案刚装好时，我仍然处在 X11 会话。三指拖动已经能用，四指却像坏了一样。这不是触控板
驱动问题，而是四指 GNOME 扩展只支持 Wayland。

换到 `Ubuntu on Wayland` 后，四指手势由合成器直接处理。工作区会跟着手指移动，松手时根据
进度决定回弹还是切换。这是它比“手势触发 Ctrl+Alt+方向键”更接近 Mac 的地方。

Wayland 并不是另一套 Ubuntu。文件、应用和 GNOME 设置都不变，只是显示和输入底层从 X11
换成 Wayland。旧的 X11 应用通常会通过 XWayland 继续运行。代价是少数老式录屏、远控、全局
快捷键和自动化工具可能需要调整。

## 我没有照抄上游安装脚本

上游方案为了读取 `/dev/input`，默认建议把当前账号加入 `input` 用户组。这很直接，但权限范围
也很大：`input` 组不只包含触控板，还可能读取键盘等输入设备。

我的整合安装器改成了 udev 的 `uaccess` 授权，只向当前桌面用户开放被系统识别为触控板的
设备，以及创建虚拟输入设备所需的 `/dev/uinput`。运行程序本身是普通用户服务，不以 root
身份常驻。

管理员权限只用于安装两个固定文件：

```text
/usr/local/bin/linux-3-finger-drag
/etc/udev/rules.d/69-mac-like-touchpad.rules
```

用户服务还设置了 `NoNewPrivileges=true`。如果代理出现问题，执行下面的命令就会立即释放真实
触控板：

```bash
systemctl --user stop three-finger-drag.service
```

不用重启，也不会把触控板永久锁在代理里。

## 安装方式

仓库没有提供 `curl | bash` 的一行命令。我更希望使用者先看到自己将要运行什么：

```bash
git clone https://github.com/Cooperiano/mac-like-touchpad-ubuntu.git
cd mac-like-touchpad-ubuntu
./install.sh
```

安装器会完成以下工作：

1. 检查 GNOME 版本和 CPU 架构；
2. 下载固定版本的三指拖动程序并校验 SHA-256；
3. 安装最小权限 udev 规则和用户服务；
4. 从 GNOME 官方扩展站下载与当前版本兼容的四指扩展，并校验 UUID；
5. 关闭 GNOME 的三指导航，把工作区、总览和显示桌面交给四指；
6. 配置自然滚动、双指右键、自适应加速等基础参数；
7. 将下一次 Ubuntu 登录会话设为 Wayland。

安装后注销并重新登录，然后运行：

```bash
./status.sh
```

它会列出当前会话类型、三指服务、四指映射、触控板设备和最近的错误日志。

## 这套方案目前完整到什么程度

对“三指拖动”这个目标，它已经比较完整。当前采用的上游 2.0.0 重写了输入代理，加入了三指/
四指落下时序处理、幽灵点击修复、触控板重新枚举和 30 项状态机回归测试。我在安装前也实际
运行了这 30 项测试。

对“完整复制 Mac 触控板”，它仍然有边界：

- 普通 ELAN 触控板没有苹果触控板的线性马达和压力感应；
- Linux、GNOME 和 macOS 的指针加速曲线并不完全相同；
- GNOME 大版本升级后，四指扩展可能需要更新兼容版本；
- 三指动作由软件合成，极端落指节奏仍可能需要微调 `entryDebounce` 和 `pressGrace`。

这些差距不能靠“再装一个驱动”消失。但操作逻辑已经可以一致：三指负责拿住东西，四指负责
管理空间。对经常在 Mac 和 Linux 之间切换的人，这比追求表面上的动画相似更有价值，因为肌肉
记忆终于不用每天重学一次。

## 最后留下三个可调参数

配置文件位于：

```text
~/.config/linux-3-finger-drag/3fd-config.json
```

最常用的是：

```json
{
  "acceleration": 1.0,
  "dragEndDelay": 0,
  "entryDebounce": 50,
  "pressGrace": 75
}
```

拖动慢就提高 `acceleration`。希望抬手后短时间内还能重新落下继续拖，可以给
`dragEndDelay` 一个较小的毫秒数。除非确实遇到三指、四指互相误判，否则不要随意降低两个识别
阈值。

仓库地址：

<https://github.com/Cooperiano/mac-like-touchpad-ubuntu>

安装、卸载、诊断、安全边界和第三方许可都已经放在里面。先读脚本，再决定是否让它接管自己的
触控板。
